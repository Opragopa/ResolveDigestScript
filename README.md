# Resolve Digest Script

Генератор выпуска из пяти новостей для одной Fusion-композиции в DaVinci Resolve.

## Один раз подготовить шаблон Resolve

В единственном Fusion Clip на `V1` переименуйте ноды:

```
title_01 … title_05     # Text+ с заголовками
body_01 … body_05       # Text+ с описаниями
image_01 … image_05     # Loader с картинками
```

`image_XX` обязательно должен быть **Loader**, а не MediaIn. Merge, анимация,
маски и Transform остаются как есть. Скрипт меняет текст и параметры изображения в этих 15 нодах, а
также текстовый `Size` у Text+ при необходимости, чтобы текст поместился в
заданный в ноде text-box (`LayoutWidth` и `LayoutHeight`). Базовый `Size` шаблона
запоминается в данных ноды, поэтому при повторных запусках шрифт не
уменьшается накопительно.
Для этого у каждого `title_XX` и `body_XX` в Inspector → Layout выберите
`Type: Frame` и выставьте нужные размеры рамки Width/Height
(в API это `LayoutWidth`/`LayoutHeight`, а `Width`/`Height` — разрешение изображения): именно эти границы скрипт
считывает из композиции, а не задаёт сам.

Перед вставкой текста скрипт заменяет обычный пробел после русского предлога
на неразрывный: `в\u00a0городе`, `для\u00a0проекта`, `через\u00a0неделю`.
Предлог не остаётся в конце строки, а перенос и масштабирование остаются
подчинены параметрам конкретного Text+ в Fusion.

## Формат DOCX

Пять повторяющихся блоков: заголовок, один или несколько абзацев описания,
адрес статьи и номер фотографии. URL и маркер разрешено держать в одной строке.

```
Заголовок новости
Описание новости. Может занимать несколько абзацев.
https://www.spbstu.ru/media/news/...
(фото 1)
```

Номер в `(фото 6)` — порядковый номер фото **в статье**, а не имя файла. Скрипт
скачивает все содержательные фотографии каждой статьи в отдельную папку
`news_XX` с файлами `photo_01.jpg`, `photo_02.jpg` и т. д. Нода `image_XX`
получает путь к этой папке. Если в DOCX указано `(фото N)`, `Trim In` и `Trim Out`
устанавливаются в `N-1–N-1`; без метки используется `0–0`. После запуска нужное
фото можно выбрать вручную в Inspector Loader.
При недостаточном числе картинок для указанного номера запуск останавливается.

## Запуск прямо из DaVinci Resolve

Скопируйте **всю** папку проекта (файл `ResolveDigest.py`, папку
`resolve_digest` и `requirements.txt`) в пользовательскую папку скриптов:

```text
macOS: ~/Library/Application Support/Blackmagic Design/DaVinci Resolve/Fusion/Scripts/Utility/ResolveDigest/
Windows: %APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility\ResolveDigestScript\
```

Для скрипта нужен Python 3.9 или новее (64-bit). Установите зависимости один раз в Python, которым пользуется Resolve. На macOS
обычно проще выполнить это в Terminal после перехода в скопированную папку:

```bash
python3 -m pip install -r requirements.txt
```

Перезапустите Resolve. Скрипт появится в меню **Workspace → Scripts → Utility
→ ResolveDigest → ResolveDigest**. Откройте проект и timeline, запустите его
и выберите DOCX. Никаких аргументов в Terminal для ежедневной работы не
требуется.

В Windows откроется системное окно выбора DOCX с владельцем на основном
мониторе. Информационные сообщения и ошибки выводятся поверх окон через
Win32 и при открытии центрируются в рабочей области основного монитора.
Для них не нужны PySide2 и QApplication. Центрирование использует
[SPI_GETWORKAREA](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)
и [HCBT_ACTIVATE](https://learn.microsoft.com/en-us/windows/win32/winmsg/cbtproc). Изображения сохраняются на диске `Z:` в папку, вычисленную
по году создания DOCX и дню/месяцу в его имени:
`Z:/Workspace/<год> year/Дайджест на экраны/<месяц>_<название>/<день> <месяц>/`.
После обновления композиции автоматический рендер **не запускается**. Откройте
страницу Deliver и запустите рендер вручную; код работы с render preset
сохранён в проекте для будущего включения.

Если указанное имя Fusion Clip оставить пустым, скрипт обновит первую Fusion-
композицию на V1. Укажите имя клипа, чтобы явно защититься от выбора другой
композиции.

Скрипт всегда загружает страницы и изображения напрямую, без системных
переменных прокси (включая SOCKS). Поэтому для него не нужны PySocks и
настройки `HTTP_PROXY`, `HTTPS_PROXY` или `ALL_PROXY` не влияют на загрузку.

## Запуск из Terminal (для диагностики)

Установите зависимости в Python, которым запускаете скрипт:

```bash
python -m pip install -r requirements.txt
```

Сначала безопасно проверьте исходный DOCX и скачивание:

```bash
python -m resolve_digest.main /path/to/news.docx --cache /path/to/cache --dry-run
```

Затем откройте проект и нужный timeline в Resolve, оставьте Fusion Clip на
первой видеодорожке и выполните ту же команду без `--dry-run`:

```bash
python -m resolve_digest.main /path/to/news.docx --cache /path/to/cache --clip-name NEWS_TEMPLATE
```

Если имя клипа не указано, используется первая Fusion-композиция на V1.
Для запуска из меню используйте `ResolveDigest.py` вместе с папкой
`resolve_digest`; `main.py` предназначен для командной строки. Внешний Python
должен видеть `DaVinciResolveScript`.


## Если скрипт не запускается

После обновления файлов перезапустите Resolve и выберите `ResolveDigest.py`
в меню Workspace → Scripts → Utility → ResolveDigestScript. Проверьте,
что рядом с ним находится папка `resolve_digest`, а в проекте открыт timeline
с нужной Fusion-композицией на V1.

Ошибки поиска папки, импорта зависимостей, подключения к Resolve, чтения DOCX,
скачивания и обновления Fusion обрабатываются общей точкой входа. Сообщение
показывает этап, тип ошибки и путь к журналу. Полный traceback, версия Python
и `sys.executable` записываются в `%LOCALAPPDATA%/ResolveDigest/ResolveDigest.log`.
Если папка недоступна, используется `%TEMP%/ResolveDigest/ResolveDigest.log`;
последний резерв — консоль Resolve.

При ошибке импорта установите зависимости в тот Python, который указан в
журнале: `"<путь к python.exe>" -m pip install -r requirements.txt`.
Не используйте `Resolve.exe` вместо `python.exe`, если хост сообщает его в
`sys.executable`: в таком случае выясните настроенный интерпретатор Resolve.
Ошибки самого запуска Python до исполнения `ResolveDigest.py` скрипт перехватить
не может. Если не появляется ни сообщения, ни журнала, откройте консоль Resolve
и проверьте загрузку Python и выбранный пункт меню.

Перед скачиванием проверяются все 15 нод и их типы (TextPlus / Loader), перед
изменениями проверяются номера фотографий. Отказ `SetInput` считается ошибкой.
Композиция разблокируется при исключении, правки объединяются в группу Undo
`Resolve Digest`, если хост поддерживает StartUndo/EndUndo. При сбое посреди
обновления уже записанные значения автоматически не откатываются: отмените
эту группу вручную в Fusion. Скачивание файлов также не является транзакцией.

Папка на Z: должна быть доступна текущему пользователю Resolve. Скрипт проверяет
доступность диска до начала загрузки. В диалоге выбора DOCX отмена пользователем
и ошибка PowerShell различаются; пути с кириллицей передаются в UTF-8.

Проверка без Resolve в Windows PowerShell (временные файлы внутри проекта):

```powershell
$env:TEMP = Join-Path $PWD '.test-tmp'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
python -B -m unittest discover -s tests -v
```


## Прогресс и отмена в Windows

После выбора DOCX открывается окно прогресса по центру основного монитора.
Оно показывает этап, общий процент, текущую новость, номер скачиваемого фото,
заголовок и адрес статьи. Процент отражает завершённые этапы и фотографии,
а не число скачанных байтов. При ожидании ответа сервера процент может стоять.

Окно работает в отдельном процессе WinForms и остаётся отзывчивым во время
сетевых запросов; для него не нужны PySide2 и изменения Python в Resolve.
Поставляйте файл `resolve_digest/progress_window.ps1` вместе с остальной папкой.
Для запуска используется Windows PowerShell с UTF-8 обменом сообщениями.
Если окно не запускается, причина попадает в обычное сообщение и журнал.

Кнопка «Отменить» и крестик окна запрашивают отмену. Текущий HTTP-запрос
должен завершиться или достичь таймаута (15 секунд на соединение, 60 секунд на чтение ответа; это сетевые таймауты, не общий предел длительности загрузки).
После этого новые загрузки и запись в композицию не выполняются. Уже
скачанные файлы остаются на диске. Перед началом записи в Fusion кнопка отмены
отключается, чтобы не прерывать частично применённое обновление.

После успеха, отмены или ошибки окно остаётся открытым до нажатия «Закрыть».
При ошибке в нём видны этап, причина и путь к полному журналу; текст можно
выделить и скопировать. При сбое самого окна используется прежний диалог
ошибки. За пределами Windows этапы выводятся в консоль.


## Нестабильное соединение с сайтом

Для статьи и каждой фотографии выполняются до трёх попыток при таймаутах,
обрывах соединения и HTTP 408/429/500/502/503/504. Паузы между попытками
обычно составляют 2 и 4 секунды; числовой Retry-After учитывается с пределом
30 секунд. В прогрессбаре видны номер попытки и причина ожидания. Во время
паузы доступна отмена. Ожидание ответа: 15 секунд на соединение и 60 секунд
на чтение (не общий предел длительности запроса). Ошибки сертификата и
HTTP 401/403/404 автоматически не повторяются.

В меню Resolve одна requests.Session используется для всех пяти новостей:
она повторно использует соединения и сохраняет cookies, выданные самим сайтом.
При загрузке фотографий передаётся Referer статьи. Cookies браузера скрипт
не извлекает. ReadTimeout сам по себе не доказывает необходимость браузерной
авторизации: сначала нужно проверить повторы и доступность сервера.


## Настройка отступа и границы фотографии

В Windows перед запуском открывается окно настроек по центру основного
монитора. Отступ title → body выбирается числом в пикселях исходного кадра:
по умолчанию **80 px**, диапазон 0–1000. Значение, последний DOCX, режим
перевёрстки и переключатель автообновления запоминаются на этом компьютере
в `resolve_digest.local.json`. Этот файл исключён из Git и сохраняется при
обновлении скрипта.

Чтобы изменить расстояние в уже заполненном выпуске, включите
**«Только переверстать текст — без DOCX и скачивания»**, задайте отступ и
нажмите «Применить». Тексты и пути Loader сохраняются. Для нового выпуска
выключите этот режим и выберите DOCX. Из командной строки доступно
`--body-gap 80`.

После верстки верхняя граница title не выходит выше верхнего края фото,
а нижняя граница body — ниже нижнего края фото. Скрипт сохраняет положение
заголовка, если блок помещается, иначе сдвигает блок внутри высоты фото.
Если title, выбранный зазор и body слишком высоки, размер текста уменьшается
с повторным измерением реальных границ (до 16 итераций, минимум Size 0.004).
Отступ при этом сохраняется. Если выбранный зазор или текст всё равно
не помещается, появляется ошибка; вся верстка доступна одной группой Undo.
После установки выражений границы и зазор повторно проверяются через Fusion.

Расчёт подготовлен по вашему ResolveDigest.setting. Для всех пяти новостей
используются статические Transform2… в ветке фото и финальные Merge из этого
шаблона. Границы обработанной фотографии измеряются в кадре 0; затем
переводятся в координаты фона Merge с учётом различия разрешений и обрезки
кадром. Общая анимация и горизонтальное положение сохраняются. В шаблоне
фото сдвигаются анимацией только по горизонтали; дополнительный масштаб,
поворот или вертикальное смещение в анимированном Transform/Merge вызывают
ошибку вместо неверного расчёта. При изменении структуры шаблона требуется
обновить соответствия PHOTO_BRANCHES в адаптере.

Text+ должен использовать Layout → Frame. Границы текста измеряются
через Output.GetDoD в полном разрешении на кадре 14, где уже закончилось
появление body_01 через Alpha1. Для body задаётся выражение Center,
ссылающееся на нижний край title и ограниченное высотой фотографии.
При ручном изменении шрифта, Size, переносов, фото или положения title
снова примените режим перевёрстки: он пересчитает размеры и ограничения.
Полный шаблон с путями к медиа в репозиторий не добавляется.

Справка API: [GetDoD, DataWindow и SetExpression](https://documents.blackmagicdesign.com/UserManuals/Fusion8_Scripting_Guide.pdf).

## Автоматическое получение обновлений

Проверка GitHub включена по умолчанию; её можно отключить в окне настроек.
При **следующем запуске скрипта** Git-установка проверяет origin/main,
выполняет fetch и обновляется только fast-forward. Локальные изменения,
новые неигнорируемые файлы, другая ветка, другой origin или расхождение
истории блокируют автоматическое обновление; reset и принудительная
перезапись не выполняются. При отсутствии сети или Git запускается
установленная версия. Статус и короткий хеш версии видны в окне настроек.

После обновления заново исполняется актуальный ResolveDigest.py и
сбрасывается кеш импортов resolve_digest, поэтому повторный запуск меню
использует новый код без обязательного перезапуска Resolve.
Автообновление относится к запуску из меню; CLI автоматически не обновляется.

На компьютере, где этот репозиторий уже лежит в папке Scripts/Utility,
изменения файлов становятся установленной версией сразу после сохранения;
push лишь отправляет их на GitHub. Для другой машины обновление наступает
при следующем запуске скрипта, а не автоматически в момент push.
Для мгновенной доставки на выключенный/неактивный скрипт понадобилась бы
отдельная служба на том компьютере; она здесь не устанавливается.

Если папка была скопирована как ZIP без .git, обновление через Git недоступно.
Для такой установки один раз сохраните старую папку отдельно и клонируйте
репозиторий в новую папку ResolveDigestScript внутри Scripts/Utility
(не удаляйте прежнюю папку поверх):

```powershell
git clone https://github.com/Opragopa/ResolveDigestScript.git ResolveDigestScript
```

Команду выполняйте из родительской Scripts/Utility, когда имя новой папки
свободно. Клонирование не переносит настройки проекта Resolve и медиа:
оно устанавливает только скрипт. Дальнейшие обновления выполняются при запуске
меню. [Поведение Git fast-forward](https://git-scm.com/docs/git-pull).


### Совместимость чтения границ Fusion

Некоторые варианты моста fuscript возвращают из Output.GetDoD пустой ответ
или объект вместо обычной таблицы Python. Для уже отрисованной фотографии
сначала используется Image.DataWindow. Для Text+ проверяются варианты
GetDoD с явными параметрами и со значениями по умолчанию, затем при
необходимости выполняется GetValue и читается DataWindow изображения.
Поддерживаются числовые таблицы, именованные координаты и объекты Point/Rect.
Если все варианты не дают реальных границ, в журнал записываются имя ноды,
кадр, типы и короткие представления ответов API; границы кадра вместо
неизвестных границ текста/фото автоматически не подставляются.
